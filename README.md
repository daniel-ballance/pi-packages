# Pi packages

A collection of Pi packages that extend the harness with capabilities it does not
ship. Each package lives under [`packages/`](packages/).

- [subagents](packages/subagents/README.md) — persistent RPC child agents with composable `subagents.json` allowlists, peer messaging, bounded workflows, supervision, and saved-session recovery. For Pi run directly; inside T3 Code it stays inactive and T3's own delegated tasks take over.
- [durable-subagents](packages/durable-subagents/README.md) — opt-in Pi extension backed by native Durable conversations, with persistent collaborators, scoped peers, human holds and parent result notifications. Install this local package separately; the original subagents package remains unchanged.
- [self-reload](packages/self-reload/README.md) — agent-requested runtime reload with automatic continuation, for rapid extension development.
- [web-search](packages/web-search/README.md) — zero-configuration DuckDuckGo web search with titles, URLs, and snippets; no API key required.
- [computer-use](packages/computer-use/README.md) — ordinary Pi tools for OpenAI's installed macOS Computer Use Companion, with automatic session consent. Quietly inactive on other platforms or when the apps are missing.
- [claude-subscription](packages/claude-subscription/README.md) — provider included in the collection that reaches Claude models through the Claude Agent SDK and Claude Code's own login. Pi stays the harness; this provider uses its own short system prompt in place of Pi's default. Read its billing note before use.
- [mcp-client](packages/mcp-client/README.md) — native Pi integration for legacy MCP and the 2026-07-28 protocol, including tools, resources, prompts, completions, subscriptions, and opt-in elicitation/sampling.
- [agent-skills](packages/agent-skills/README.md) — Matt Pocock's engineering skills translated for Pi, vendored as a submodule and regenerated by script rather than forked by hand.

## Install in Pi

Install the complete collection from Git (Pi installs runtime dependencies):

```sh
pi install https://github.com/daniel-ballance/pi-packages
```

For a local checkout, install dependencies first; Pi references local paths but
**does not run npm for local installs**:

```sh
npm ci --ignore-scripts
# Or, with pnpm 12.6.0:
# pnpm install --frozen-lockfile --ignore-scripts
node scripts/patch-pi-host-security.mts
pi install "$PWD"
# Or select one package:
pi install "$PWD/packages/mcp-client"
```

Restart Pi or run `/reload`. Install either the collection or its individual
packages, not both: those are different package identities and would load the
same tools twice. Use `pi config` to select resources from the collection. MCP
servers still require explicit [configuration](packages/mcp-client/README.md#configure).
The computer-use package detects the locally installed ChatGPT runtime and
Companion automatically; it needs no MCP configuration.

## Package layout and dependencies

Every package reserves the four Pi resource directories:

```text
packages/<package-name>/
├── package.json
├── extensions/<extension-name>/index.ts
│                              src/…
├── skills/<skill-name>/SKILL.md
├── prompts/<prompt-name>/<prompt-name>.md
├── themes/<theme-name>/<theme-name>.json
└── test/
```

Unused directories contain only `.gitkeep`. Package manifests declare their own
resources; the root manifest exposes the collection.

Code several packages need lives once under [`shared/`](shared/) and is copied
into each consumer listed in `shared/copies.json` (Pi loads every package from
its own module root, so a package cannot import from outside itself). The copies
are generated: edit `shared/<file>`, run `node scripts/sync-shared.mjs`, and
commit both. The root check fails on drift. `shared/host.ts` is the host helper:
`detectHost()` returns `"t3"` for a Pi launched by T3 Code (`T3_MCP_URL` set)
and `"cli"` otherwise, and `registerHostAware()` registers a tool that
duplicates a T3 primitive with `exposure: "deferred"` under T3, so the model
reaches it only through `tool_search` or codemode. A package that consumes it
runs its tests twice, the second time with a fake `T3_MCP_URL`. Only public `index.ts`
entry points are extensions, not supporting modules such as the child guard.

The root supports both npm and pnpm workspaces. Use `npm ci --ignore-scripts`
with `package-lock.json`, or `pnpm install --frozen-lockfile --ignore-scripts`
with `pnpm-workspace.yaml` and `pnpm-lock.yaml` (verified with pnpm 12.6.0).
No single-manager `packageManager` pin is imposed. `.npmrc` selects nested npm
trees; pnpm uses its isolated, symlinked dependency layout. Both keep package
runtime dependencies resolvable from their extension entry points.

After a development install, run `node scripts/patch-pi-host-security.mts`
(or use `./scripts/ci-install.sh locked`, which runs it after installation and
any CI runtime overrides). The pinned Pi SDKs publish an npm shrinkwrap containing
vulnerable `brace-expansion` and `undici`; npm honors it even when our outer
lock or overrides name patched releases. This explicit step copies the separately
integrity-verified `brace-expansion` 5.0.12 and `undici` 8.10.2 development
dependencies into affected local SDKs and updates only their shrinkwrap entries.
It preflights all eight development hosts, accepts already-patched versions on
the reviewed 5.x and 8.x lines, and leaves those dependencies unchanged. Each
SDK's replacements are staged together with one merged shrinkwrap; a failed
promotion restores that SDK's installed libraries. Successful patches clear
hidden npm lock caches. It never runs dependency
lifecycle scripts, changes Pi versions, repairs dependencies during checks, or
follows SDK links outside the selected development checkout. The gate checks
the installed dependency, not just audit/lockfile metadata. Pi's separately
installed runtime and global configuration are **not** patched by this step.

Choose one manager per checkout. Before switching, remove only the root and
`packages/*/node_modules` directories, then reinstall with the chosen manager;
do not delete either committed lockfile. pnpm disables automatic peer installs
and dependency lifecycle scripts. The workspace's release-age exceptions name
only the eight explicitly requested Pi 0.99.2 packages and four pinned native
Durable 1.0.0 packages; all other versions and
packages retain pnpm's normal quarantine. Cold-cache CI verifies that policy.
Script execution does not implicitly reinstall
dependencies, so CI's runtime overrides remain intact.

Runtime imports belong in
that package's `dependencies`; Pi-provided APIs remain `peerDependencies`, with
pinned development copies for checks. Never commit `node_modules` or rely on a
global npm install. Pi's Git installation runs `npm install --omit=dev` at the
repository root, which installs the workspace runtime dependencies too.

Child lockfiles remain for standalone installs (`npm ci --ignore-scripts` in a
copied-out package). For standalone development SDKs, run the security step from
an installed original workspace against the copied package, for example
`node /path/to/pi-packages/scripts/patch-pi-host-security.mts "$PWD"`.
Production installs omit these SDK development copies and use Pi's runtime peers.
When changing dependencies, refresh both lockfiles from the repository root:

```sh
npm --prefix packages/<name> install --package-lock-only --ignore-scripts --workspaces=false
npm install --package-lock-only --ignore-scripts
pnpm import
```

`pnpm import` refreshes the pnpm lockfile from the updated npm lockfile. Commit
both root lockfiles together and verify both managers. Use a separate checkout
for each manager when checking dependency changes.

Each manager's root lockfile governs collection installs; child npm lockfiles
govern isolated npm development, not workspace resolution.

## Clean clone and runtime

The generated skills check needs the upstream submodule (ordinary installation
uses the committed generated skills and does not need it):

```sh
git clone https://github.com/daniel-ballance/pi-packages.git
cd pi-packages
git submodule update --init --recursive
node --version
npm --version
```

Use Node.js 22.19.0 or newer for the full supported CI matrix, then run
`npm ci --ignore-scripts` or `pnpm install --frozen-lockfile --ignore-scripts`
from the root, followed by `node scripts/patch-pi-host-security.mts`.
The CI-equivalent installer is [`scripts/ci-install.sh`](scripts/ci-install.sh)
(`./scripts/ci-install.sh locked`).

Launch Pi from this repository root when the project settings in `.pi/settings.json` or project-local skills should apply:

```sh
cd /path/to/pi-packages
pi
```

Pi project settings and policy do not walk up from a nested package working
directory, so starting Pi inside `packages/<name>` does not discover the root
`.pi/` configuration. This repository does not ship a project subagent override;
the personal global policy takes precedence over package defaults when present.
Personal model choices and permissions belong to that global policy;
`self-reload` remains project-local. A project
policy, if added, replaces the global policy as a whole; policies are not a
filesystem sandbox.

## Repository check

The canonical root check is:

```sh
./scripts/check.sh
```

`npm run check` and `pnpm run check` are equivalent package-manager wrappers.
The gate detects pnpm from the invoking manager or installed layout; set
`PACKAGE_MANAGER=npm` or `PACKAGE_MANAGER=pnpm` to select explicitly. The check validates
tracked repository configuration JSON while leaving example/proposal fixture data
alone, checks the generated `shared/` copies and runs their tests, runs the `subagents` package's `parsePolicy` through its local `tsx` when
`.pi/subagents.json` is present, then delegates to every package's `check` and
`test` scripts, and runs the existing `mcp-client` `format:check`.
The `agent-skills` package owns its scripts for generated-output drift and tests;
the root check only invokes those package scripts.

Packaging regressions exercise Pi's real loader for the root and individual
packages, inspect npm tarball contents, and exercise Pi's actual Git URL install
against a temporary local Git fixture. The npm jobs use npm's
offline cache primed by the initial install. pnpm jobs additionally test a fresh
production pnpm install and allow registry downloads for packaging fixtures
(`PI_PACKAGING_NPM_OFFLINE=false` for Pi's npm installer, whose cache is separate
from pnpm's store). Neither layout may silently depend on development modules
or a globally installed Pi.

The package scripts are the source of truth for package-specific test details.
The root gate runs deterministic local tests: it does not use a globally installed
Pi executable, credentials, or live web-search results.

## CI support and limits

CI runs the complete root check with both npm and pnpm 12.6.0 on Node.js
22.19.0 against two explicit dependency layouts:

- **locked** — committed package lockfiles: subagents pins Pi **0.99.2**;
  the other stable extension packages retain their existing development pins.
  The opt-in `durable-subagents` package independently pins Durable 1.0.0 and tests its extension adapter on Pi 0.99.2 and 1.0.0.
- **Pi 0.99.2** — Stable Pi dependencies below 1.0 are overridden in an
  isolated CI job after baseline installation; committed manifests, workspace
  configuration, and lockfiles remain unchanged. The native Durable 1.0 stack is
  kept separate from these stable Pi overrides.

The collection now requires Pi 0.99.2 for subagents. The matrix is not evidence
for every intervening Pi release or older Node.js runtime. Tests use local deterministic providers and fixtures;
live search/MCP services and optional installed-Pi executable overrides are
outside the root gate. Packaging fixtures may download registry dependencies as
noted above.

## Subagent execution versus model research

The subagents package owns execution policy, exact runtime model/thinking
validation, supervision and reported usage. Its bundled skill covers setup and
operation, not model rankings or benchmark analysis.

Model-selection research, snapshot/inventory helpers, analysis preferences and
the explicit `refresh-subagent-models` workflow now live in the separate **Pareto**
project (`~/Work/pareto` on this workstation). Use that project's README for its
Python/Make commands and compatibility notes; the former JavaScript helper paths
in this repository are no longer supported. Pareto is not a runtime dependency
and does not apply execution policy automatically. Historical exploration and
September 20 proposal records are preserved verbatim in Pareto's
`docs/subagents-model-selection/archive/`; archived policies are evidence, not
current execution configuration.

Shipped execution defaults remain in
`packages/subagents/extensions/subagents/src/policy.ts`. A personal
`subagents.json` or trusted-project `.pi/subagents.json` replaces those defaults
as a whole. This separation does not modify global Pi settings or policies.
