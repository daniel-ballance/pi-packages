# Pi packages

A collection of Pi packages that extend the harness with capabilities it does not
ship. Each package lives under [`packages/`](packages/).

- [subagents](packages/subagents/README.md) — persistent RPC child agents with composable `subagents.json` allowlists, peer messaging, bounded workflows, supervision, and saved-session recovery.
- [self-reload](packages/self-reload/README.md) — agent-requested runtime reload with automatic continuation, for rapid extension development.
- [web-search](packages/web-search/README.md) — zero-configuration DuckDuckGo web search with titles, URLs, and snippets; no API key required.
- [mcp-client](packages/mcp-client/README.md) — native Pi integration for legacy MCP and the 2026-07-28 protocol, including tools, resources, prompts, completions, subscriptions, and opt-in elicitation/sampling.
- [agent-skills](packages/agent-skills/README.md) — Matt Pocock's engineering skills translated for Pi, vendored as a submodule and regenerated by script rather than forked by hand.

## Clean clone and runtime

The generated skills check needs the upstream submodule:

```sh
git clone https://github.com/daniel-ballance/pi-packages.git
cd pi-packages
git submodule update --init --recursive
node --version
npm --version
```

Use Node.js 22.19.0 or newer for the full supported CI matrix. There is no root
install or root lockfile; packages own their dependencies and lockfiles. For a
local dependency setup, use `npm ci --ignore-scripts` in each package that has a
lockfile. The CI-equivalent installer is [`scripts/ci-install.sh`](scripts/ci-install.sh).

Launch Pi from this repository root when the project settings in `.pi/settings.json` or the project policy in `.pi/subagents.json` should apply:

```sh
cd /path/to/pi-packages
pi
```

Pi project settings and policy do not walk up from a nested package working
directory, so starting Pi inside `packages/<name>` does not discover the root
`.pi/` configuration. This project explicitly enables development child tools
and peer messaging. On this workstation, the personal global policy is
read/search-only and `self-reload` is project-local. Policies replace the global
policy as a whole, and are not a filesystem sandbox.

## Repository check

The canonical root check is:

```sh
./scripts/check.sh
```

`npm run check` is the equivalent package-manager wrapper. The check validates
tracked repository configuration JSON while leaving example/proposal fixture data
alone, runs the `subagents` package's `parsePolicy` through its local `tsx` when
`.pi/subagents.json` is present, then delegates to every package's `check` and
`test` scripts, and runs the existing `mcp-client` `format:check`.
The `agent-skills` package owns its scripts for generated-output drift and tests;
the root check only invokes those package scripts.

The package scripts are the source of truth for package-specific test details.
The root gate runs deterministic local tests: it does not use a globally installed
Pi executable, credentials, or live web-search results.

## CI support and limits

CI runs the complete root check on Node.js 22.19.0 against two explicit Pi
runtime points:

- **Pi 0.85.1** — the supported minimum and the version pinned by committed
  package lockfiles.
- **Pi 0.87.1** — the current runtime, installed into an isolated CI job after
  the baseline `npm ci --ignore-scripts`; the override uses no committed manifest
  or lockfile change.

The matrix is evidence for those two versions, not every intervening Pi release
or older Node.js runtime. Tests use local deterministic providers and fixtures;
external services and optional installed-Pi executable overrides are outside the
root gate.
