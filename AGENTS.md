# Repository guidance

- Use [`README.md`](README.md) for the clean-clone, runtime, and CI contract.
- Run the canonical root check with `./scripts/check.sh` (`npm run check` is its wrapper); CI installation is defined by [`scripts/ci-install.sh`](scripts/ci-install.sh) and [`.github/workflows/ci.yml`](.github/workflows/ci.yml). Package scripts remain the source of truth for package checks.
- A new worktree needs `git submodule update --init --recursive` before the root check, which otherwise fails with "Stale registry row". Remove one with `git worktree remove --force`, since it holds submodules. Under pnpm, run the check with `PI_PACKAGING_NPM_OFFLINE=false`, as CI does; the Git-install test otherwise misses npm's cache.
- GitHub Actions runs fail within seconds at the account level, so the local root check is the gate. A ruleset requires owner approval; the owner merges with `gh pr merge --merge --admin` and has authorized agents to do the same.
- Dependencies follow the latest stable release: move them with `node scripts/update-dependencies.mjs` (`--check` reports drift). Add no exact pins or release-age exclusions.
- Pushes run the root check through the committed [`scripts/git-hooks/pre-push`](scripts/git-hooks/pre-push) hook (enabled with `git config core.hooksPath scripts/git-hooks`; see README "Pre-push hook"). Fix a failure rather than pushing with `--no-verify`.
- Before changing generated skills, read [`packages/p3stack/AGENTS.md`](packages/p3stack/AGENTS.md). Change rules, registry rows, overlays, patches, or authored sources, then regenerate. Never hand-edit `packages/p3stack/skills/`.
- The repository root is the installable Pi package. `package.json#piBundle` lists its five packages. After changing that list or a member's `pi` block, run `node scripts/root-package.mjs`. The root check fails when the root `pi` block is stale. `packages/p3stack` nests its subagents and todo workspaces. Every package keeps its own checks and tests. `packages/mcp-client` stays an optional separate replacement, not a global default.
- Lint skills with the repository tool [`scripts/lint-skill`](scripts/lint-skill/README.md). It belongs to no package; a package's `check` script calls it with explicit skill directories.
- [`global/`](global/README.md) holds the owner's live Pi configuration, linked into `~/.pi/agent` from the main checkout. Pi writes to it while running, so expect uncommitted changes there on `main`; commit them through a worktree branch, and read `git diff global/` in the main checkout before you change those files. `git pull` there refuses over those edits: copy the edited file aside, `git checkout --` it, `git fetch` and `git merge --ff-only origin/main`, then restore the copy. `global/tests/test_model_policy.py` mirrors the realm in Pareto's `.pi/model-selection.json`; change both together, on the owner's word.
- Launch Pi from the repository root when project settings or policy should apply; nested package working directories do not walk up to discover root project configuration.
- A new tool or `ctx.ui` call follows the host-parity rules in [`GLOSSARY.md`](GLOSSARY.md) ("Host parity") and [ADR 0001](docs/adr/0001-host-parity.md): detect the host with [`shared/host.ts`](shared/host.ts), whose per-package copies [`scripts/sync-shared.mjs`](scripts/sync-shared.mjs) writes and `./scripts/check.sh` verifies; never edit a copy.
