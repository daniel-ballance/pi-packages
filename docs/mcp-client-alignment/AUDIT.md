# MCP client alignment audit

## Decision and evidence boundary

**Evolve `packages/mcp-client` as the replacement client. Park `mcp-additions`.** Mine native Pi **1.1.0** for host integration; use official MCP specifications for wire requirements. The additive-hook recommendation in [the earlier compatibility study](../mcp-additions/COMPATIBILITY.md) is superseded by this decision, not implemented by this document.

Audit: 2026-10-08. Read repository `AGENTS.md`/`README.md`, implementation and relevant tests. Package baseline: checkout at `af8a36da367b62226af91d2e2db45f33d3f11401`, with concurrent work in progress. Native baseline: `/tmp/pi-1.1.0-mcp-review`, pinned upstream **`abe508e1b89912adde45528136c3221eb69acdd7`**. The earlier study records byte-for-byte verification of these snapshots; this audit inspected their source, not just its conclusions. Official sources below use **`c518f7a927cff918bce35d3522fcdb046d264d7c`** and revision-specific website pages. Current pages can receive compatible amendments.

**No full-conformance claim.** Tests establish particular fixture behavior, not exhaustive revision/transport/security coverage. No installation, personal configuration, desktop/Mac interaction, or commit was performed. Only this document is owned by this audit.

**Highest priorities:** (1) fail-closed configuration/exposure migration in both directions; (2) Pi 1.1.0 tool/codemode/result contract; (3) finish cancellation and input safety work, then test the integrated lifecycle. Optional feature breadth is not the immediate blocker.

Parent is implementing the **peer cancellation guard**; another child owns **input/forms review/edit/mode/secret safety**. Both are **underway, not verified by this audit**. Passing existing tests below does not certify either change; parent must run their new regressions and integrated checks. Tables describe the implementation when first inspected, not subsequent concurrent edits (including later `content.ts`/`index.ts` changes); close findings only against tested final code.

## 1. Configuration: same filename does not mean interchangeable

Package source: [`config.ts`](../../packages/mcp-client/extensions/mcp-client/src/config.ts) and [`index.ts`](../../packages/mcp-client/extensions/mcp-client/src/index.ts), especially `loadConfig`, `resolveConfig`, `session_start`, `refresh`. Native: [core config/registry][pi-config], [file loading/overrides][pi-files], [runtime][pi-runtime].

| Contract | Native Pi 1.1.0 | Existing package / migration consequence |
| --- | --- | --- |
| Files and trust | Agent `mcp.json`, then trusted project `.pi/mcp.json`. | Same files and `ctx.isProjectTrusted()` gate. Preserve this; never read an untrusted project during conversion/startup. |
| Transport inference | `command` → stdio; `url` → HTTP; accepts `streamable-http` alias; rejects `sse`. | Missing `type` defaults to **stdio**, so URL-only entries fail. Explicit HTTP/alias and standalone SSE supported. Converter must add type, never guess from an invalid mixed entry. |
| Timeout | **Seconds**, default 60; progress resets the request timer. | **Milliseconds**, integer 100–3,600,000, default 60,000; hard deadline, not extended by progress. Explicit native `60` fails validation; native `100` is accepted but becomes **100 ms**, not 100 s. Reverse migration can turn 60,000 ms into 60,000 seconds. Convert units explicitly and report out-of-range values; do not clamp silently. |
| Enable/disable | `enabled: false`; disabled servers remain listed. | `disabled: true`; disabled entries are filtered out of runtime inventory. Native `enabled` is rejected as unknown. In reverse, native validation accepts unknown `disabled` but does not use it: a disabled package server can **start**. |
| Exposure | Default `codemode`; `direct`, `deferred`, `hidden`; `codemode-deferred` alias. Exact `toolExposure` wins, then first matching wildcard, then server default. | Only `toolLoading: eager` (default) or `deferred`; no native exposure or per-tool policy. These fields currently **fail closed**, not silently expose tools. Stripping them to make config load would expose previously hidden tools; `deferred` is discovery/activation, **not denial**. |
| Project overrides | Transport-less project entry may override only `enabled`, `exposure`, `toolExposure`, retaining the global connection/credentials. Complete project definitions replace named entries. | Every entry must be a complete server definition; named entries replace wholesale. A partial override fails the load. Never drop an invalid disabling override and fall back to the enabled global entry. |
| Validation isolation | Reports/skips invalid entries; continues others. Names restricted to letters/digits/`_`/`-`, with normalized namespace collisions rejected. | Strict whole-file schema; one invalid entry prevents session configuration loading, including otherwise valid servers. Names are arbitrary nonempty strings; hashed tool IDs avoid ordinary sanitization collisions. Fail-closed loading is an intentional safety property to retain until per-server quarantine is specified. |
| Host options | `description`, top-level `autoEnableCodemode`, and richer auth settings supported. | Unknown fields rejected. No description/namespace or native auto-activation semantics. Do not silently erase these on conversion. |
| Values / auth | `~/` expansion; env/header `!command` resolution; automatic HTTP OAuth when appropriate; provider auth and richer OAuth/CIMD settings. | `${NAME}` / `${NAME:-fallback}` expansion without shell evaluation; no home expansion; explicit `oauth` opt-in with only client ID, callback port and scope. `!command` stays literal. OAuth storage is package `mcp-auth/`, not native `mcp-auth.json`; do not copy tokens or enable shell expansion implicitly. |
| Extension registrations | `getMcpServers()` and `mcp_servers_change`; file config wins over registered namespaces; replacement/unregistration reconnects/disconnects. | No registry read/event handler found. Owning `/mcp` replaces native session MCP, so registered servers are **not automatically inherited** by this package. Either implement this contract or report unsupported registrations prominently. |

**Reverse migration is a safety blocker too.** A read-only invocation of native snapshot `validateMcpServerConfig` with `{command:"node", disabled:true, timeout:60000, toolLoading:"deferred"}` succeeded; evaluating native defaults returned `{enabled:true, exposure:"codemode", timeoutSeconds:60000}`. Native does not reject these package-only fields. Removing the replacement is therefore **not** a safe rollback without restoring native-format configuration. Native also supplies cwd roots automatically, whereas the package advertises roots only when explicitly configured.

Evidence: [`config-format.test.ts`](../../packages/mcp-client/test/config-format.test.ts), “Claude-style …”, “old format … unknown fields fail closed”, and “environment defaults … without shell evaluation”; [`config.test.ts`](../../packages/mcp-client/test/config.test.ts), “config merging replaces named servers and validates strictly”. These passed here. There are no corresponding migration/exposure/registration acceptance tests in the reviewed package suite.

## 2. Pi host integration: reuse the contracts, not merely the names

Native sources: [tool adapter][pi-tools], [extension runtime integration][pi-index], [extension API][pi-api]. Package sources: `src/index.ts` (`toolName`, `refresh`, `mcp_search_tools`, `tool_result`) and [`content.ts`](../../packages/mcp-client/extensions/mcp-client/src/content.ts).

| Area | Observed gap / deliberate difference | Acceptance target |
| --- | --- | --- |
| Tool identity | Native `mcp__<server>__<tool>` sanitizes and hashes collisions/overlong names. Package always uses `mcp_<sanitized-prefix>_<16-hex-hash>`. Existing permission rules, scripts and transcripts are not name-compatible. | Publish an explicit old→new map before changing names. Test punctuation, long names, collisions, withdrawn/re-added tools and resumed branches. Never add callable aliases that bypass restrictions. |
| Exposure and search | Native registers `exposure`, `namespace`, boolean annotation hints and output schema; activates built-in codemode/search as appropriate. Package registers none of those host fields, manually adjusts active tools, and uses its own `mcp_search_tools`. It returns server annotations as search data but not Pi tool annotations. | Implement Pi 1.1.0 exposure/namespace contract; hidden must be unreachable by direct call, package/native search, codemode and resource helpers. Preserve permission hooks; hints are untrusted metadata, not authorization. Test active-set changes, tree/resume/fork, and discovery races. |
| Codemode return | Native `convertMcpResult` exposes the **full MCP result minus top-level `_meta`** as Pi `structuredContent`, with a `CallToolResult` output schema. Package returns Pi `content` and `details.raw` (or artifact pointer), **not** host `structuredContent`; its MCP output schema is used only for local validation. | Return the native-shaped object to scripts, including `content`, `structuredContent`, `isError`, while retaining bounded model previews. Test `result.content`, structured data, and `image(result.content[i])` through actual Pi 1.1.0 codemode. Do not assume `details.raw` supplies that contract. |
| MCP errors | Native returns `isError: true` and structured result; codemode can inspect MCP error results without a thrown execution error. Package uses `details.mcpError` plus a `tool_result` patch for direct model errors. | Test both direct and codemode routes, including preservation of structured error content. Transport exceptions must remain distinguishable from MCP application errors. |
| Images and artifacts | Package **does** emit Pi image blocks for top-level PNG/JPEG/WebP/GIF, including prompt images. Budget: four images / 5 MiB encoded data and 2,000 lines / 50 KiB text. Lossy results go to private JSON artifacts. Native uses 20 KiB middle-truncated text, keeps full script results and decodes resource image blobs; other binary resources get files. Package resource blobs fall through to artifacts. | Preserve bounded previews as an intentional policy; bridge script results separately. Add real codemode image forwarding and embedded-resource image tests. Review `_meta`/artifact visibility before exposing raw results to scripts; native deliberately removes top-level `_meta`. |
| Resource surface | Native `list_mcp_resources`, `list_mcp_resource_templates`, `read_mcp_resource`, with exposure filtering and MCP App-resource exclusion. Package combines operations in `mcp_resources`, with explicit server/cursor, no equivalent exposure filtering/App exclusion. | Decide aliases versus documented incompatibility; any hidden policy must govern these alternate routes too. Do not render MCP Apps merely to match catalog breadth. |
| Replacement ownership | Package registers `/mcp`; [native docs][pi-doc] identify that as replacement ownership. Native shell-level `pi mcp` remains native. Package `/mcp` is a different command set/UI, not the native manager. | Run a real Pi 1.1.0 loader test: one `/mcp`, one connection per server, no duplicate tools, registry events handled. Warn that native CLI config edits/diagnostics need not describe this replacement's session behavior. |

Evidence already present: [`pi.test.ts`](../../packages/mcp-client/test/pi.test.ts), “namespaces are stable … collision resistant”, “content mapping preserves …”, and direct error patch assertions; [`audit-regressions.test.ts`](../../packages/mcp-client/test/audit-regressions.test.ts), “content keeps order, prompt images, metadata …”, “artifact references survive native Pi compaction serialization”. These tests were inspected, not rerun here. [`native-pi.test.ts`](../../packages/mcp-client/test/native-pi.test.ts) passed and exercises a real SDK session, deferred activation, prompt image blocks, TTL refresh and subscription reload—but loads **the installed package SDK 0.85.1**, with custom extension factories and no model requests. Its filename does **not** prove Pi 1.1.0 builtin/codemode parity. The repository CI matrix likewise does not establish that parity.

## 3. Lifecycle and wire guarantees: preserve tested behavior, close explicit gaps

Native [client][pi-client] always initializes and accepts exactly `2025-11-25`, `2025-06-18`, `2025-03-26`, `2024-11-05`; it has no Current implementation. Package [`connection.ts`](../../packages/mcp-client/extensions/mcp-client/src/connection.ts), [`peer.ts`](../../packages/mcp-client/extensions/mcp-client/src/peer.ts), [`http.ts`](../../packages/mcp-client/extensions/mcp-client/src/http.ts) implement both eras. Do **not** replace the package wire stack with native v1.1.0 and lose Current support.

- **Legacy:** package initializes, checks the returned accepted revision (explicit pin requires an exact match), sends `notifications/initialized`, sets transport version, and supports server requests. SDK-backed Streamable HTTP retains session semantics; old HTTP+SSE is explicit opt-in and rejected for explicit Current mode. `2025-03-26` batches are version-gated. Session 404 recovery initializes anew without replaying the failed operation; DELETE is best-effort on shutdown. Existing audit regressions cover those details. This is implementation evidence, not every legacy optional capability on every revision.
- **Current (`2026-07-28`):** package probes `server/discover`, supplies required per-request version/capabilities, routes Unicode/header-bound parameters, uses request-scoped HTTP JSON/SSE without legacy session headers/GET streams, and implements MRTR with fresh IDs, opaque per-operation state and bounded rounds. Modern subscriptions check acknowledgments/correlation/filters. Native does none of this. Official [base requirements][mcp-basic], [versioning][mcp-versioning], [MRTR][mcp-mrtr], [HTTP binding][mcp-http] are the authority, not native behavior.
- **Cancellation:** existing peer tests cover outgoing abort/progress/late responses, and legacy incoming cancellation; HTTP cancellation aborts the request stream rather than POSTing a cancellation notification. Legacy initialize must not send cancellation; Current stdio must signal cancellation for outstanding requests. See [Current cancellation][mcp-cancel] and [legacy lifecycle][mcp-legacy]. Parent's new peer guard and child's input cancellation/consent changes remain **unverified** here. Required integrated regressions: cancel/timeout/close while awaiting input, late UI resolution, batch dispatch, MRTR retry, subscription teardown, and repeated close; no response/retry after cancellation and no orphan dialog.
- **Process/startup teardown gap:** package `stdio.ts` closes stdin then kills only its immediate child; [native stdio][pi-stdio] uses process groups/tree cleanup. Package `session_shutdown` closes `state.peer`, but startup assigns it only after `connect()` finishes; an in-progress startup is not immediately cancelled by that loop. Add delayed-connect/reload and wrapper+grandchild fixtures, with bounded cleanup. This is separate from the peer guard; no Mac testing is needed to cover Linux process-group ownership.
- **Intentional policy differences:** package hard deadlines, conservative no replay of tool operations, explicit roots, bounded result/catalog/schema sizes, no automatic icon/link fetching, and no automatic injection of server instructions are worth keeping. Native progress-reset timeouts/reconnect behavior are compatibility inputs, not instructions to weaken these choices.
- **Era/negotiation coverage still needed:** `Peer.request`'s `input_required` branch is not explicitly restricted to Current; add legacy negative tests before claiming strict era separation. Recognized modern errors are deliberately surfaced rather than downgraded; version selection from `UnsupportedProtocolVersionError.data.supported` needs an explicit policy/test (the spec recommends mutually supported retry). Test HTTP body/status combinations and explicit pins; never turn capability/header errors into silent legacy fallback or replay a side-effecting operation.

Optional capabilities are not universal obligations. Native's missing forms, sampling, prompts/completion UX and subscriptions are **feature gaps**, not by themselves nonconformance. Package has paths for these, plus opt-in Current tasks, but each advertised sub-capability needs its own revision/surface tests. The input/forms child owns the immediate review; URL elicitation requires separately tested consent, attribution and browser isolation, not an agent-readable preview. Legacy URL-required/completion flows and Current MRTR are different contracts.

The official [versioning guide](https://modelcontextprotocol.io/docs/2026-07-28/learn/versioning) identifies Current as `2026-07-28`; older published revisions are not a universal supported-version promise or EOL schedule. [Deprecated registry][mcp-deprecated]: roots, sampling, logging and DCR remain specified but are deprecated in Current; old HTTP+SSE was deprecated earlier. Keep demanded existing legacy support; do not expand deprecated features merely for checklist completeness. No inference of “all protocols supported” from version constants or SDK installation.

## 5. Prioritized backlog and non-invasive migration

| Priority | Concrete delivery | Done when |
| --- | --- | --- |
| **P0 — migration safety** | Specify explicit native↔package schema conversion/preflight, including units, inverse enable flags, partial overrides, transport inference, names, auth and unsupported fields. No permissive “ignore unknown” fix. | Fixtures prove no disabled server starts and no hidden tool/resource becomes reachable in either direction; unsupported restrictions block conversion. Errors do not print secrets. Converter is a recommendation, **not implemented here**. |
| **P0 — host adapter** | Implement exposure/namespace/annotations/output-schema and full MCP codemode result mapping; preserve bounded model images/text and native error distinction. Decide version-gated host support and naming migration. | Actual Pi 1.1.0 direct/search/codemode/permission/image tests, including hidden bypass attempts and resumed branches. Existing 0.85.1 tests remain green or the minimum supported host is explicitly raised. |
| **P0 — concurrent safety work** | Parent peer guard plus child's input/forms policy, then one integrated regression run. | Cancellation prevents late replies/retries; form review/edit and explicit accept/decline/cancel work; unknown modes fail closed; secret collection and headless consent cannot bypass policy. **Pending parent verification.** |
| **P1 — ownership/lifecycle** | Consume or explicitly reject extension server registrations; close replaced/unregistered connections; abort startup/discovery and clean up subprocess trees. | Native file precedence, dynamic registrations, repeated reload/shutdown, delayed startup and wrapper/grandchild tests; exactly one owner/connection. |
| **P1 — protocol matrix** | Add era-negative, unsupported-version, HTTP fallback, per-revision capability, URL-flow and malformed payload tests; map applicable normative clauses to tests. | Public support table distinguishes tested transport/revision/features, intentional limitations, and unresolved conformance risks. |
| **P2 — UX/parity** | Disabled inventory, native-compatible resource naming, reconnect/status guidance, explicit richer OAuth demand. | No credential-store migration or new command execution by default; regression-tested user benefit. Keep additions parked. |

Practical rollout, without touching today's configuration:

1. Keep current runtime/configuration unchanged. Build synthetic native and package fixtures; run a **read-only** inventory/preflight that never launches servers, evaluates `!commands`, expands secret values into output, or reads an untrusted project's config.
2. Present a human-reviewed conversion diff and effective-access matrix (server enabled state; each tool/resource route; timeout; protocol; identity/auth). `hidden` cannot be approximated by deferred loading. Until restrictions are representable, **block migration**, or offer an explicitly approved whole-server disable—not wider access.
3. Exercise converted fixtures in an isolated agent directory/project using loopback/stdio servers, first on existing supported hosts, then real Pi 1.1.0 with builtins/codemode. Include registration-based servers and direct/indirect permission hooks. No personal tokens or automatic OAuth-store import.
4. After safety gates, user backs up both global/project native config and explicitly chooses replacement ownership. Switch one server at a time; check effective access and images/errors. Native `pi mcp` remains native and is not the replacement's validator.
5. Roll back by restoring the **native-format backup before** unloading the replacement. Never leave package `disabled`, millisecond timeout or package-only policy fields for native to interpret. Keep existing package users' format/names working until an explicit, tested migration is approved.
