# Mechanical procedures become tools

Use code for steps the model might otherwise skip. While the mode is on, terminal spawns, including proxied spawns and workflow workers, get a writer or report-only header at initial dispatch. Follow-ups and peer messages are not new briefs. A coordinator passes its own grant or a narrower one. A report-only brief keeps a reviewer on the assigned question instead of starting a playbook.

Under T3, `p3stack_roles` returns self-contained `briefHeaders` with the saved grant. The parent selects the stance, substitutes a task grant when needed, and sends the complete brief to `delegate_task`. The hook checks the header and blocks an incomplete or stale brief instead of rewriting approved text. The approval dialog shows the first 4,000 characters of the pretty-printed arguments. For a longer supervised call the hook requires `task` last, so the other arguments precede the brief; the child still gets the whole task. No extra tool call or second approval is required to prepare a brief.

`floor-check.mjs` flags recognized quality-floor violations in the diff. Exit 0 does not certify the change. `p3stack_roles` with `distinctFrom` prefers a different model family when the catalog offers one. Workflow templates let the subagents engine run interrogate, arena, hillclimb, and skill evals. The offline description lint checks vocabulary, not the model's choices.

Prose stays for judgment: the house policies, the references, and the playbooks.

## Considered options

- **More prose in the skills**: rejected. Each rule costs context on every read, and agents under pressure skip it. All four upstreams already say a repeated instruction should become a check.
- **Tools only on one host**: accepted only where the host lacks the primitive. Workflow templates are terminal-only because T3 has no workflow engine; the host map states the gap and the prose procedure remains the fallback (ADR 0001).

## Consequences

Each tool has tests on both hosts where it touches host behavior. A tool's output is still untrusted work output until a check or a review confirms it.
