# Changelog

## Unreleased

- `subagent_spawn` returns the compact child entry that `subagent_wait` uses, without `reports`, plus `model`, `thinking`, `worktree` when created, and overlap warnings. It no longer includes the task, usage, or session/log/stderr paths. Read `lastSubmission` and other full-summary fields through `subagent_list`. A proxied spawn returns that same entry. The TUI task line comes from the call, not the result.
- `subagent_wait` waits until there is news. `timeoutSeconds` has no maximum and no default. Without it, the wait returns only when the selected children settle, one needs input, a human hold appears, or a message for the waiting agent is queued; `0` checks once. Escape cancels the wait and leaves the children working. The result's `wake` (`hold`, `input`, `settled`, `message` or `timeout`) replaces `timedOut`, `needsInput` and `needsHold`, and in mode `any` a child that needs input now outranks a settled sibling. One queued batch of messages ends one wait.
- `subagent_wait` returns `{ wake, agents }` with a compact status per child, without the task, usage, paths or timestamps that `subagent_list` still returns. Each child's new reports come inline as `reports`, with an `unread` count for reports left out, replacing the top-level `reports`, `deferred` and `hasMoreReports`. `collect` defaults to true, so a default wait acknowledges what it returns and no duplicate report message follows. A root wait leaves a live coordinator's children to that coordinator.
- A coordinator Child's `subagent_wait` relays to the root in waits of at most 60 seconds, so the private pipe's 90-second call budget no longer caps it. A message queued for the coordinator, from the root or a peer, ends its wait with `wake: "message"`.
- `maxChildren` accepts `0` to disable spawning, `-1` for no live cap, and any positive safe integer. The old 1 to 64 ceiling is gone. An omitted field still means 4, and the built-in policy still means 6. `null` is invalid. `null` no longer means an omitted `maxChildren` field.
- Show each child the same way on every surface, from one state table. Tool results draw a two-line card: glyph, name and state word with the short `model · effort` on the right, then activity, elapsed time, turns and cost. `/subagents` draws one row per child or run: glyph, name, `[model effort]` badge and activity, under short group rules, with the legend as its subtitle. `/subagents list` lines start with the glyph and name and strip terminal controls from child text. `subagent_read` now also returns the child's `model` and `thinking`.
- Launch each Child with `--models <its model>`, so the user's `enabledModels` setting no longer prints "No models match pattern" warnings for providers the Child does not load.
- Make the built-in policy (used only when no `subagents.json` exists) work for multi-model workflows with no setup: a menu across the common providers, dropping unreachable entries without diagnostics; `todo` and the delegation tools; `maxDepth` 2; bounded wake loops; six live Children; and the collection's `claude-subscription` provider when it is installed beside this package. A user's own file still keeps every optional field off until it is set.
- Mark a catalog model whose provider an extension registered, such as `claude-subscription`, with `requiresExtension` unless `providerExtensions` maps it, and refuse a spawn of it that selects no extension. Children start with `--no-extensions`, so such a Child previously failed at launch with "model not found".
- Answer `subagents:catalog` requests on Pi's event bus with the usable models, so other extensions' commands (which cannot call tools) can offer only models a Child may use.
- Add bounded nesting: with the new optional `maxDepth` policy field (default 1, unchanged behaviour), a parent may give a Child proxied delegation tools. Calls travel over the Child's private pipe to the one root Manager, which composes grandchildren from the same allowlist and scopes every call to the caller's subtree. Close, abort, halt and kill cascade down the whole subtree, stopped descendants included, and the subtree cannot delegate while they run; resume revalidates a nested Child at its own depth. List, costs, the live cap and the inspector (as an indented tree) cover the whole tree. A nested Child's routine reports go to its own parent; its input requests reach the root.

- Add `subagent_loop` and `/loop`: bounded wake loops that start a parent turn on an interval until the parent stops them or a bound ends them. Off unless the new optional `loops` policy field enables them; `subagent_catalog` shows the bounds. Existing policies are unchanged.
- Make the built-in characterization test pass on Pi 1.2.0 as well as 0.99.2.
- Add an optional `worktree` field to `subagent_spawn`: the child runs in a new git worktree under `<repository of cwd>/.pi/worktrees/` on a new branch. The checkout is validated against `workingDirectories`, removed with its branch if the spawn fails, and otherwise left for the parent to merge and remove. No policy change.
- Add `--disable-native-subagents` for launch-scoped opt-out of all native management, workflow and notification startup. Unflagged TUI/RPC launches and unrelated extensions are unchanged.
- Stay inactive in Pi sessions launched by T3 Code with its MCP bridge (`T3_MCP_URL` set), as if `--disable-native-subagents` were passed. T3's delegated tasks are the subagent system there; direct Pi launches are unchanged.
- Detect T3 through the collection's shared host helper (a generated copy in `src/host.ts`). Behaviour is unchanged. The test suite now also runs with a fake `T3_MCP_URL`, and the real-parent RPC tests no longer pass a caller's T3 variables to the Pi processes they launch.
- Keep a herdr pane `working` while subagents or workflows run after the parent settles, labelled with what is running (for example `2 subagents`), when herdr's Pi integration is installed. TUI only; nothing is sent until a subagent first runs.
- Add `alwaysExtensions`/`alwaysTools` policy fields: allowlisted entries every child receives without parent selection. An unavailable always-on entry disables spawning instead of being skipped. Existing policies are unchanged.

## 0.3.0 — 2026-10-01

- Require Pi 0.99.2; update development dependencies and npm/pnpm locks.
- Add opt-in managed native codemode, tool-search and MCP extensions. Reject unknown built-ins and llama.cpp; no implicit grants in existing version-1 policies.
- Enforce selected tool sources inside children, including nested calls. Filter discovery and authorize MCP tools by original names, including sanitized-name collisions.
- Add provider-extension linkage, MCP project/credential consent, codemode settings and optional cache-warming suppression. Disable codemode classifiers and reject virtual models.
- Preserve RPC input dispositions across child/peer/workflow reporting; consumed inputs do not leave phantom running work or count as completed workflow tasks.
- Refresh authoritative cumulative cost on standalone usage entries, including idle cache warming; avoid nested-call double counting.
- Add offline native-runtime fixtures and regression tests. Legacy MCP package and personal policies are unchanged.
