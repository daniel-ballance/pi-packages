The smoke checks that T3's `delegate_task` works under claude-subscription. claude-subscription shows Pi tools to Claude as `mcp__pi__<name>`, so Claude sees that tool as `mcp__pi__mcp__t3-code__delegate_task`.

## Findings

- T3 reads `launchArgs` when it starts a thread's Pi process. After the settings change, a new Linux thread started with the new extension path without a provider restart. A Pi process that was already running kept the old path.
- The first Mac attempt, a T3 thread at 22:46Z, failed with `Claude Code is not signed in with a Claude subscription`. It passed after the operator ran `claude auth login` on the Mac and the empty credentials file below was moved aside. The record does not show which of the two changes fixed it.
- On the Mac, Claude Code keeps the login in the login Keychain. A process started over SSH cannot read that Keychain item, because macOS answers `User interaction is not allowed`. A headless check over SSH reports the same "not signed in" error even when the login is valid. Run the Mac smoke from a T3 thread, which runs in the GUI session.
- `~/.claude/.credentials.json` appeared on the Mac at 22:48:05Z, one second after a headless Pi run over SSH. It held an empty access token with `expiresAt: 0`. It was moved aside as `.credentials.json.empty-stub-20261020.bak`. If the Mac reports no subscription after a fresh `claude auth login`, look for that file.
