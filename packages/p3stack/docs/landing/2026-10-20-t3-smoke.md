## Findings

- T3 reads `launchArgs` when it starts a new thread's Pi process. A new thread used the new extension path without a provider restart. Existing threads keep the old path until they restart.
- On the Mac, Claude Code keeps the login in the login Keychain. A process started over SSH cannot read that Keychain item, because macOS answers `User interaction is not allowed`. A headless check over SSH therefore reports `Claude Code is not signed in with a Claude subscription` even when the login is valid. Run the Mac smoke from a T3 thread, which runs in the GUI session.
- A headless Pi run over SSH created `~/.claude/.credentials.json` with an empty access token and `expiresAt: 0`. The file was moved aside as `.credentials.json.empty-stub-20261020.bak`. If the Mac reports no subscription after a fresh `claude auth login`, look for that file first.
