# Review my change

Keep the checkout read-only, including in reviewer briefs. Skip cleanup, pull requests and repairs; return the report in your reply. Set `GIT_OPTIONAL_LOCKS=0` for all Git queries, including helpers and reviewer commands.

1. **Pin the input.** Run `node "<p3stack-mode directory>/scripts/checkout-fingerprint.mjs"` in the checkout and each populated submodule recursively. Keep the outputs by path. Pin the requested paths, HEAD and the merge-base with the user's ref (otherwise the default branch); ask for a ref if none resolves. Include in-scope staged, unstaged and untracked changes unless the caller requested a committed range. Capture in-scope submodule diffs against their gitlinks at the base, not just the parent's dirty markers.
2. **Scan the floor.** In each reviewed checkout run `node "<p3stack-mode directory>/scripts/floor-check.mjs" --base <base> --json` per [the floor](references/floor.md). For a submodule, pass the gitlink SHA recorded at its parent's pinned base: run `git rev-parse --verify "$parent_base:$submodule_path"` from the parent checkout root. Use that SHA as the parent base for nested submodules. Report in-scope hits, including explained ones. If the scan fails or misses part of the pinned input, report the gap.
3. **Review the diff against its contract.** Follow [code-review](../code-review/SKILL.md) with the pinned base, input and task contract. Give every reviewer the [review stance](references/review-stance.md), not the author's conclusion. Report Standards and Spec separately with `file:line` evidence or command output.
4. **Confirm preservation.** Repeat the fingerprints and compare every field and checkout path. Report the index and working tree unchanged only if all match. Report drift or a failed comparison; never restore over someone else's work.
