# Assess an existing repository

Return the map, evidence and proposed files in the answer. An assessment writes nothing: no setup, tracker updates, report files or repairs. Read the linked skills at the steps below, from the p3stack-mode skill directory; use only the named assessment steps.

1. **Record the starting content.** Run `node "<p3stack-mode directory>/scripts/checkout-fingerprint.mjs"` in the checkout and in each populated submodule. Retain the outputs in the session. Each records HEAD, hashes of the staged and unstaged binary Git diffs, and a hash of the non-ignored untracked file list with each path, mode and content hash (link text for symlinks). This covers Git-visible content, not ignored caches. If a fingerprint fails, report the blocker rather than asserting the tree is unchanged.
2. **Tracker.** Inspect the README, agent instructions, remotes and documented tracker, including a local Markdown tracker. A remote alone does not establish that issues are enabled. When a tracker exists, use only Explore in [setup-matt-pocock-skills](../setup-matt-pocock-skills/SKILL.md). Skip legacy-file moves, setup questions, confirmation, writes, remote setup and label creation. Return the existing configuration and draft any missing decisions. Otherwise mark setup skipped with evidence.
3. **Architecture.** Use the read-only exploration and synthesis in [how](../how/SKILL.md). Trace one actual user entry point through its modules to storage or an external system. Cite paths, dependency direction and the repository's build/test commands. If read-only delegation is unavailable, skip its spawns and trace the flow yourself.
4. **Verification.** Use Interview the repo in [create-verification-skill](../create-verification-skill/SKILL.md): find the primary surface, launch, drive, observation and isolation. Skip setup repairs, generating a skill, seeding the feature map, proving a generated skill and offering its maintenance loop. Reuse an existing verification recipe if present. Exercise one user path only if it writes nothing and uses no shared state; include command and observed output. Otherwise mark it blocked or unproven with the reason.
5. **Domain.** Under the default grant ask whether to include [domain-modeling](../domain-modeling/SKILL.md); stop this turn with the map so far and the content check below. On a decline mark this step skipped. Under full autonomy proceed without asking. Compare terms in code and domain docs. Skip glossary updates, ADR creation and the product interview; return proposed entries, contradictions and unresolved meanings instead.
6. **Architecture health.** Use Explore in [improve-codebase-architecture](../improve-codebase-architecture/SKILL.md). Use recent history and the runtime trace to identify friction. Return evidence, recommendation and uncertainty, including when no candidate warrants work. Skip HTML generation, browser launch, candidate selection, grilling and implementation.
7. **Content check and handback.** Repeat the fingerprints from step 1 in the same checkouts. Compare every field with the starting result, including when the tree started dirty. If any differ, report the delta; do not reset someone else's files or claim a clean assessment. Return the tracker decision, architecture trace, verification evidence, vocabulary, survey and proposed next tasks.
