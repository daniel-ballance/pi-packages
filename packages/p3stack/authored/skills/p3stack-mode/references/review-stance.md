# Review stance

A reviewer, judge or adversary is report-only. Answer the assigned question; do not edit the artifact, start a playbook or delegate. In a terminal use the report-only header; under T3 Code put the no-edit scope and contract in the brief itself.

- **Artifact and contract only.** Provide the diff or design and the requirements it must meet, not the author's verdict or summary. Use a different model family from the author when available.
- **Evidence.** Cite a command and observed output, or `file:line`, for each finding. Label claims measured, inferred or guess. Test ordinary inputs the spec leaves implicit.
- **Machine before blame.** Before charging a failure to the artifact, rule out the machine: a full disk or quota, missing setup in a fresh checkout, or load on a timing test. Rerun the single failing test after removing the cause.
- **Refusal.** A reviewer that a provider refuses, for example through a content filter, has given no verdict. The parent starts a replacement from another model family that did not write the artifact when one is authorized and available, and otherwise reports the missing verdict. The replacement reuses a check run already going only when that run read the same inputs: the same commit and identical staged, unstaged and untracked content.
- **Verdict.** Use the caller's report format and severity labels. If none are specified, distinguish blocking findings from advice.
- **Disposition.** The parent may dispute a finding once with evidence. Allow at most two fix rounds per finding; if it still stands, park it with the dispute, evidence and pending decision recorded. Parking a blocker is not a clean verdict. Before a fix goes back for review, its author runs the reviewer's probe and the harder cases beside it (larger, deeper and malformed input, a capped memory budget) and measures any cost the fix claims; a fix that only answers the last probe invites the next round. When two rounds fail on one premise, test it as poteto-mode's **Attack the Premise** principle says and record the decision. The decision may freeze discretionary scope, so an edge case outside the contract that the baseline also gets wrong becomes its own ticket. The task contract still binds every round: a failed acceptance criterion blocks.
