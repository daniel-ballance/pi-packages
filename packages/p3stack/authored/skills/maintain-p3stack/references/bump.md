# Bump one checkout

1. Start only after a successful current-pins audit and an explicit bump request. **Root:** read `packages/p3stack/skills/poteto-mode/playbooks/opening-a-pr.md` for the forge. Process independent checkouts sequentially. For each, fetch origin and create an isolated branch from current `origin/main`. Use `chore/p3stack-<name>-tip-<run-id>` (cursor for vendor/pstack, pocock for vendor/matt-pocock, otherwise the checkout basename). Initialize its submodules and workspace. If this base differs from the audited repository commit, [audit this base](references/audit.md) before moving a pin. Leave the operator's branches alone.
2. Resolve the repository from origin. Inventory open maintenance PRs against its main for this same checkout; branch prefix and title are hints, not proof. Check the gitlink, changed paths and bump note. Record PR numbers and heads; never supersede an unrelated repair. Resolve the requested ref, or the manifest branch tip with `git ls-remote`, to its full commit SHA. Check merged maintenance reverts for that checkout and SHA. A previously reverted candidate is blocked pending an owner fix; report the revert. A specifically requested ref overrides the tip guard only.
3. **Package:** run `npm run bump -- <source> <checked-sha>` once per checkout, including tip runs. Capture old and new full SHAs and scope report even on generation failure. Do not replace a fetch/ref error with a manual checkout. As soon as the gitlink moves, **package:** `git add -- <checkout>` before any pin check. Inspect `git -C <checkout> diff --name-status <old> <new>` and the full upstream commits for every source sharing the checkout.
4. Account for every review-scope path, packaging change and borrowed idea. Read each changed borrowed path and its restatements; update them or explain why they still hold. Classify new, renamed and removed skills in `registry/skills.json`, with a reason for each emit, reference or drop decision. Repair only generator inputs. Keep deny tokens and required links in `rules/lint.json`; never hand-edit generated skills, agents or vendor contents. For generation errors use [failure classes](references/failure-classes.md), including min-match, reviewed section hash/diff and missing-link repairs.
5. Inspect the bump’s generated changes against the decision list. If you repaired an input, run `npm run generate` in the package first. Save the complete intended diff (including new files); stage intended changes, regenerate again, and require no new tracked or untracked delta. On a route/chain change update its fixtures and run `npm run eval:routing` as a separate gate even if another check fails. Require every case to pass. A lockfile mismatch goes to the root dependency-refresh procedure, not this PR.
6. For no change, report the checked SHAs and clean tree without a note or PR. Otherwise prepare the [bump note and PR body](references/bump-note.md). Commit the note and all intended changes. Require empty `git status --porcelain=v1 --untracked-files=all` and record the full repository `git rev-parse HEAD`. Run the [loader and smoke](references/smoke.md) on this candidate. Under T3 Code, [verify live behavior](references/verify-host.md) for changed host operations.
7. After those gates pass, push only this branch with the repository’s `scripts/git-hooks/pre-push` enabled. Use the hook’s successful `./scripts/check.sh` as the pre-merge root receipt: record the full candidate commit, command, exit status and hook result in the PR body. A push without evidence that the hook ran is not a receipt. Reuse that result only for the same clean commit; a repair, amend or rebase needs a new receipt. On failure preserve evidence, open no PR and report blocked.
8. Open one ready PR per changed checkout: `chore(p3stack): bump <sources> to <new-sha7>`. Use the prepared body file. Follow [landing](references/land.md), then start the next checkout from the new main. An unrequested pause at an open PR is not completion.
