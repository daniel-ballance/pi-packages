### Worktree and simulator cleanup

1. Snapshot and audit. Record `df -h /`, then run `scripts/worktree-audit.sh [-b <pr-base-ref>] [repo-path]` (principle-build-the-lever). Without `-b` it checks `MERGED` against `origin/HEAD`, so pass `-b origin/<branch>` when PRs target another branch. It reads paths from `git worktree list`, never hand-typed, since a hand-typed `myrepo-worktrees/x` misses one that lives at `.pi/worktrees/x` (principle-encode-lessons-in-structure). It classifies each worktree by size, age, merge state, uncommitted work, PR state, and the newest chat that touched it, then suggests a bucket. The transcript scan is slow, so background it.
2. The bucket is advice, not permission. Get the in-use worktrees from the user and add the workers' worktrees per [Isolation](references/host-capabilities.md#isolation). Keep every candidate in that set even if the audit marked it `safe`. A worktree whose owner you cannot establish counts as in use.
3. Verify usage before deleting. For every `verify-recent-chat` row, or anything you doubt, fan subagents out to read the transcripts and report whether the session is ongoing and which worktrees it touches (principle-guard-the-context-window, transcripts are bulk). An ongoing session spawns arena and repro trees into sibling worktrees via background subagents, and those are in use even when no session names them. Resolve each subagent's role per the Subagents section.
4. Hold `unknown` until inspection succeeds. For `hold-untracked` or `hold-ignored`, list every untracked and individually ignored file by name (`git -C "$wt" status --porcelain=v1 --untracked-files=all --ignored=matching --ignore-submodules=none`). Wholly ignored directories count toward `ignored-dirs`, not a hold. Show tracked edits too; preserve them before removal. Never remove an in-use worktree.
5. Get the operator's approval for the confirmed worktree paths and, for `hold-untracked` or `hold-ignored`, the named files. Preserve those files first or delete only those explicitly approved for deletion. Recheck ownership and rerun the audit with the same base and session directory. Only for a worktree whose row is `safe` and that is no longer in use, run `git worktree remove -- "$wt"` with the exact audited path. If it refuses, stop. Confirm with `df -h /` and re-list.
6. Simulators and caches. Measure the specific devices, runtimes or cache paths worth reclaiming. Report their sizes; remove only the named items the operator approves.

This is the one playbook that deletes user state with no code review to catch a slip, so the gates above are the review.

**Reply:** `df -h /` before and after with space reclaimed, the worktrees pruned, and a one-line reason for each held back (in-use by which chat, or uncommitted work).
