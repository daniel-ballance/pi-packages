# Quality floor

Run `node "<p3stack-mode directory>/scripts/floor-check.mjs"` in the checkout on the **final diff, after the last edit**, including review fixes. Pass `--base <ref>` to compare directly with that commit (use the intended parent of a stacked change). Otherwise the base is the first available merge-base of HEAD with `origin/HEAD`, `main`, or `master`, then `HEAD~1`, then the empty tree. `--json` includes the resolved base.

The detector compares the base to the working tree (committed, staged and unstaged changes combined), and scans non-ignored untracked files. It skips binary contents and submodules. A symlink or a file over 1 MiB on either side gets an `unchecked-file` finding instead of a content scan. The detector does not follow symlinks.

- **Added lines in any text file:** TS ignore/nocheck or expect-error without a reason; ESLint disable, Biome ignore, noqa, type-ignore, pylint disable, Rust allow, nolint or SuppressWarnings; focused, skipped or todo test markers; literal not-implemented stubs; empty single-line catch or Python except/pass. Examples in documentation can match too. See `RULES` in the script for the spellings.
- **Lost tests:** deleted files under test/tests/__tests__/spec directories or with test/spec suffixes, `test_*.py` or `*_test.go/py`; moving one of these files out of the recognized test paths also counts. In surviving test files it checks removed line-leading `test`/`it` calls with a quoted name not added back in the same file. A rename of a case may need explanation. This is not suite collection.
- **Policy:** deletion of `CONSTRAINTS.md` (override with `--constraints <repo-relative-path>`), removed nonblank lines, and changes to numbers on otherwise matching lines in a hunk. A lower minimum or higher maximum/budget is a hit; inspect unclassified changes. In Jest/Vitest/Vite/Karma configs, nyc, Python project/coverage configs, tsconfig, Biome and ESLint configs, the script checks removed or loosened numeric threshold lines (coverage/threshold, lines, branches, functions, statements, fail_under/--cov-fail-under, min/max or budget), listed TS strictness flags set to false, removal of a literal `"strict": true` from tsconfig, and ESLint rule values set to `off` or `0`, lowered from `error`/`2` to `warn`/`1`, or removed at error severity. These are same-hunk line patterns, not effective config; they do not parse package.json or collect parameterized or multiline test declarations.

**Exit 0:** no unexplained recognized pattern; not proof of quality. **1:** inspect each finding. **2:** could not check; correct the error and rerun. In report-only review, report the hits without editing. A writer removes each hit or records why it should stand: `floor-ok: <reason>` on the added line, or `--explain 'deleted-test old.test.js:0=covered by integration tests'`. Repeat the option for each exact `category path:line`; line 0 denotes a whole-file finding, other removals use base line numbers. Include explained hits and reasons in the verdict.
