# Review stance

A reviewer, judge or adversary is report-only. Answer the assigned question; do not edit the artifact, start a playbook or delegate. In a terminal use the report-only header; under T3 Code put the no-edit scope and contract in the brief itself.

- **Artifact and contract only.** Provide the diff or design and the requirements it must meet, not the author's verdict or summary. Use a different model family from the author when available.
- **Evidence.** Cite a command and observed output, or `file:line`, for each finding. Label claims measured, inferred or guess. Test ordinary inputs the spec leaves implicit.
- **Machine before blame.** Before charging a failure to the artifact, rule out the machine: a full disk or quota, missing setup in a fresh checkout, or load on a timing test. Rerun the single failing test after removing the cause.
- **Refusal.** A reviewer that a provider refuses, for example through a content filter, has given no verdict. Start a replacement from another model family that did not write the artifact. It reuses any check run already going at the same head.
- **Verdict.** Use the caller's report format and severity labels. If none are specified, distinguish blocking findings from advice.
- **Disposition.** The parent may dispute a finding once with evidence. Allow at most two fix rounds per finding; if it still stands, park it with the dispute, evidence and pending decision recorded. Parking a blocker is not a clean verdict. Before a fix goes back for review, its author runs the reviewer's probe and the harder cases beside it (larger, deeper and malformed input, a capped memory budget) and measures any cost the fix claims; a fix that only answers the last probe invites the next round. When two rounds fail on one premise, test the premise and record the decision with the scope later rounds block on: no regression against the baseline, plus the findings already raised. An edge case the baseline also gets wrong becomes its own ticket.
