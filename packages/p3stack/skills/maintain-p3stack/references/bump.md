# Bump one checkout

1. Start only after a successful current-pins audit and an explicit bump request. **Root:** read `packages/p3stack/skills/poteto-mode/playbooks/opening-a-pr.md` for the forge. Process independent checkouts sequentially. For each, fetch origin and create an isolated branch from current `origin/main`. Use `chore/p3stack-<name>-tip-<run-id>` (cursor for vendor/pstack, pocock for vendor/matt-pocock, otherwise the checkout basename). Initialize its submodules and workspace. Leave the operator's branches alone.
2. Resolve the repository from origin. Inventory open maintenance PRs against its main for this same checkout; branch prefix and title are hints, not proof. Check the gitlink, changed paths and bump note. Record PR numbers and heads; never supersede an unrelated repair. For a tip bump use `git ls-remote` against the manifest repository and branch. Check merged maintenance reverts for that checkout and tip. A previously reverted candidate is blocked pending an owner fix; report the revert. A specifically requested ref overrides the tip guard only.
3. **Package:** run `npm run bump -- <source> [ref]`. Capture old and new full SHAs and scope report even on generation failure. Do not replace a fetch/ref error with a manual checkout. As soon as the gitlink moves, **package:** `git add -- <checkout>` before any pin check. For shared sources run the bump for each source at the same candidate SHA. Inspect `git -C <checkout> diff --name-status <old> <new>` and the full upstream commits for *every* source, even when a later invocation reports no movement.
4. Account for every review-scope path, packaging change and borrowed idea. Read each changed borrowed path and its restatements; update them or explain why they still hold. Classify new, renamed and removed skills in `registry/skills.json`, with a reason for each emit/drop. Repair only generator inputs. Keep deny tokens and required links in `rules/lint.json`; never hand-edit generated skills, agents or vendor contents. For generation errors use [failure classes](references/failure-classes.md), including min-match, reviewed section hash/diff and missing-link repairs.
5. **Package:** `npm run generate`, then inspect generated changes against the decision list. Save the complete intended diff (including new files); stage intended changes, regenerate again, and require no new tracked or untracked delta. On a route/chain change update its fixtures and run `npm run eval:routing` as a separate gate even if another check fails. Require every case to pass. A lockfile mismatch goes to the root dependency-refresh procedure, not this PR.
6. For no change, report the checked SHAs and clean tree without a note or PR. Otherwise follow the [bump-note and PR body requirements](references/bump-note.md). Stage the note and all intended changes. **Package:** run `npm run check`, `npm test`, `node generator/check-registry.mjs` and `node generator/check-t3-pin.mjs`. Require exit 0, no missing references, and zero unclassified skills. Rerun tests after any JSON repair. Run the [loader and smoke](references/smoke.md) in this worktree. **Root:** require `./scripts/check.sh` to end with `Root check passed.`
7. If any gate fails, preserve the candidate and receipts, open no PR, and mark that checkout blocked. Otherwise commit and push only this branch with hooks. Open one ready PR per changed checkout: `chore(p3stack): bump <sources> to <new-sha7>`. Use the prepared body file. Follow [landing](references/land.md), then start the next checkout from the new main. An unrequested pause at an open PR is not completion.
