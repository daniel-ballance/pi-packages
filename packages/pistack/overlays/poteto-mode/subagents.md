## Subagents

**Brief every subagent you spawn inside a playbook step per the [poteto-agent recipe](../../agents/poteto-agent.md)** (code-writing delegates, ad-hoc helpers). The recipe makes the child read this file first, so put this file's absolute path in every brief. The chat that receives `/skill:poteto-mode` runs the playbook. Never delegate the playbook itself. Routed workflow skills (`how`, `why`, `interrogate`, `reflect`, `swarm`) compose their own subagents for diverse-model review. Respect what the skill prescribes, don't override it with the poteto-agent recipe.

**Defaults for every delegation.** Delegate per **Delegate** in the [host capabilities](references/host-capabilities.md): run subagents in the background and wait for their results, pass file pointers rather than inlined context, give each only the tools its brief needs, and name an explicit model per role (configurable via `/skill:setup-pstack`. Defaults `grok-4.7-xhigh-fast` for code, `claude-opus-5-5-xhigh` for prose and judgment; resolve these hints per **Models and role defaults**). Code delegates tier by difficulty. The hardest changes (cross-cutting design, gnarly concurrency, subtle algorithms) go to your strongest judgment model (`claude-opus-5-5-xhigh`), whether the task needs judgment on vague intent or is a precisely specified sequence of steps to execute to the letter. Trivial mechanical edits go to your fast code model. Roles in the role defaults override these defaults and the model choices in the routed skills (`how`, `why`, `arena`, `swarm`, `architect`, `interrogate`, `reflect`). A role with no entry keeps its default, and a role of `inherit-parent` or `auto` runs on your own model. Each code playbook's model comes from its role (`feature, refactoring`, `bug-fix`, `perf-issue`, or `hillclimb`), and the hardest changes read `hardest tasks`. Prose and judgment read `judgment and prose`.

**Match the model to the job.** Before each spawn, start from the role's entry or default and pick the thinking level the job needs. The `/skill:setup-pstack` budget sets each role's starting level, xhigh by default. Raise it one step, up to max, for the hardest or subtlest work. Lower it one step for judgment and two or more steps for routine work. Pi has no fast variants, so a `-fast` hint means the same model at the same level. Verification is the exception and stays on the `swarm workers` model and level (`grok-4.7-xhigh-fast` by default). Change only the thinking level and keep the family the role names, so a diverse panel stays diverse. If the model does not offer that level, use the nearest level it offers. A role on `auto` or `inherit-parent` stays on your own model. If the catalog does not offer the adjusted model, do not try another adjustment. Use the role's entry or default and say so.

You own every subagent's work. Review the diff and write your own summary, don't pass through what it said. A second opinion is the same prompt against a different model. Agreement is high-signal.

**Fresh subagents by default.** Give new work to a fresh subagent with consolidated scope, meaning the original brief, every later directive, and the prior agent's report and branch. This holds for a fix round, a follow-up, a retry, and the next queue item. Resume, message, or queue a follow-up on an existing subagent only when the new work strictly needs state that lives in that agent and is costly to move: its local checkout, its uncommitted changes, or a process it still runs, such as a dev server, a simulator, or a babysit watcher. A stop or hold order to a running agent is not reuse. A role such as a PR owner outlives its agent. Once that agent returns, a fresh agent takes the role's next round. Interrupt-chained resumes silently drop directives, so fire a fresh subagent with consolidated scope rather than trusting a "done" summary.
